## Phase A — 지금 바로 (피그마 무관, 확실한 것)

### A1. `useCurriculum` 견고성 — 🔴 작지만 실버그 (0.5일)
`major` 행이 2개면 `.maybeSingle()`이 null 반환 → 커리큘럼/홈 화면이 조용히 깨진다.
파일럿 검증 중 실제로 겪음. "최신 주전공 1개 선택"으로 보강 + test:db 케이스.

### A2. 알림 시스템 — SPEC §2.7 (2~3일)
커피챗 신청/수락/거절·새 메시지를 **새로고침해야만** 안다. 커피챗이 실제로
돌아가려면 필수. 채팅에서 쓰는 Realtime 패턴 그대로.
- `notifications` 테이블 + RLS + Realtime 구독
- 네비 벨 아이콘 + 안읽음 뱃지 + 드롭다운
- 인앱만 (이메일 X — 발송 인프라 비용)

### A3. 나머지 41개 학과 커리큘럼 — (학과당 0.5~1일, 큰 덩어리)
파일럿 방식 반복: 공식 PDF → 이미지 판독 → 시드 → 요약표 대조 → ASCII 배포.
- **학과별로 나눠 진행** (한 번에 다 하면 오류 위험 + 검증 불가)
- 우선순위: 소융/컴공(완료) → 학생 많은 공과·전자정보 → 나머지
- ⚠️ 틀린 졸업요건은 학생 졸업을 막음 → 반드시 원본 PDF 대조, 추측 금지
- 과거 학번 버전은 나중(현행 버전부터)

## Phase B — 피그마 확인 후 (🔍 MCP 재연결이 선행)

> 토큰 만료 상태. 재연결하면 D1·D3·D4·D7이 풀린다. (`~/.claude.json` figma 설정)

### B1. UI/UX 정밀 감사 (1~2일)
화면별 색상·간격·폰트를 피그마 구조화 데이터와 1:1 대조. 이번엔 홈/네비만
훑었고 로그인·회원가입·탐색·마이페이지·상세는 눈대중 수준. MCP 있으면 정밀하게.

### B2. 트랙 필터 (D3) — 탐색 `모든 분야 ▾` (1일)
`tracks`·`useTracks`·트랙 저장 다 준비됨. 피그마의 분야 드롭다운이 트랙인지 확인 후
탐색에 연결. ⚠️ 기존 가입자는 track_id=null이라 '미지정' 처리 필요.

### B3. 캘린더 (D1) — 정체 확정 필수 (3~4일)
`mypage_calendar_01~04` 4화면. **무엇의 캘린더인지**부터 확인:
(a) 커피챗 일정 / (b) 학사 일정 / (c) 개인 할일 — 셋 다 스키마가 다름.
제안: (a) 커피챗 일정 → `coffee_chats.scheduled_at` 추가.

### B4. 메시지함 전용 페이지 (D4) (2일)
지금 채팅은 커피챗 모달로만 접근. 네비 `메시지함`은 임시로 /my 연결해둠.
피그마가 전용 페이지 의도면 `/messages` 신설 + 대화 목록 UI.

### B5. 온보딩 + 프로필 개인화 (D7) (3~4일)
`main_onboarding`, `mypage_profile_personalisation` ×4 — 재학생 프로필 필드 확정 후.
제안: 트랙 선택을 온보딩으로 이동(가입 폼이 이미 길다).
